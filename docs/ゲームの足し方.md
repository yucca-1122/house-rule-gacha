# ゲームの足し方

新しいゲームの改造ルールガチャを足す手順。上から順にやれば、そのまま公開できる形になる。

## しくみ

| 場所 | 中身 | 手で書く？ |
|---|---|---|
| `app/gacha.html` | 画面の本体（全ゲーム共通の型）。doctype・html・head・body は書かない | 画面を直すときだけ |
| `games/<id>/rules.js` | そのゲームのデータ（`window.RULE_GACHA = { … }`） | 書く |
| `games/<id>/pairs.json` | 両立判定の回帰チェックの組（任意） | 書く |
| `games/<id>/theme.css` | そのゲームだけの色（任意。下の「見た目を変えたいとき」） | 書く |
| `games/<id>/index.html` | ブラウザで開く完成版（リポジトリに入れる） | 書かない（build が作る） |
| `index.html` | ゲームの一覧（トップ。リポジトリに入れる） | 書かない（build が作る） |
| `dist/artifact/<id>.html` | doctype なしの1枚（git に入れない） | 書かない（build が作る） |
| `.nojekyll` | 空のファイル。GitHub Pages の Jekyll の処理を止める | 消さない |
| `tools/` | 検査・build・確認用のサーバー | — |

画面は `rules.js` を `<script src="rules.js">` で読む。だから、どの完成版も同じフォルダに `rules.js` が要る。

## 手順

### 1. フォルダを作る

`games/<id>/` を作る。`<id>` は半角の英小文字・数字・ハイフンだけ（例: `carcassonne`）。
`<id>` はそのまま URL（`games/<id>/`）と保存の名前（`house-rule-gacha:<id>:v1`）になるので、あとから変えない。

### 2. rules.js を書く

`games/catan/rules.js` を写して、中身を入れかえるのが早い。形はこう。

```js
window.RULE_GACHA = {
  meta: { … },
  features: { … },
  levels: [ … ],
  cats: [ … ],
  basics: [ … ],
  combos: [ … ],
  rules: [ … ]
};
```

#### meta（ゲームの設定）

| 項目 | 要る？ | 例 | 説明 |
|---|---|---|---|
| `id` | 要る | `'catan'` | フォルダ名と同じにする |
| `title` | 要る | `'カタン改造ルールガチャ'` | ページの名前（タブの名前・見出し・一覧） |
| `subtitle` | — | `'通常版（3〜4人）で遊べるハウスルール'` | 見出しの下の一行。うしろに「215件」が付く |
| `updated` | — | `'2026-10-16'` | 遊び方タブと一覧に出す日付 |
| `players` | — | `{ choices: [3, 4], default: 4 }` | 人数の選択肢。無い・1つだけなら人数の行を出さない |
| `draw` | — | `{ choices: [1, 2, 3, 4, 5], default: 2 }` | 一度に引く枚数。書かなければこの値 |
| `startLv` | — | `[1, 2]` | 初めて開いたときにオンの難易度。書かなければ ★1・★2 |
| `copyTitle` | — | `'今日のカタン改造ルール'` | 「テキストでコピー」の1行目（【】の中） |
| `searchExamples` | — | `['盗賊', '港', 'サイコロ']` | 検索欄に出す例 |
| `disclaimer` | — | `'〇〇の公式のものではありません。…'` | 遊び方タブのいちばん下の注意書き |
| `colorWords` | — | `{ '木材': 'forest', '小麦': 'wheat' }` | 早見表の中のことばに、色の六角形を付ける。色は `forest` `brick` `pasture` `wheat` `ore` `sand` のどれか |
| `order` | — | `1` | 一覧に並べる順（小さいほど前。同じなら id 順） |
| `oldStoreKeys` | — | `['catan-rule-gacha.v1']` | 前の版の保存の名前。新しい名前の保存が無いときに1回だけ引き継ぐ |

#### features（両立判定の語彙）

`req` と `ban` に書ける要素の一覧。キー → 説明。

```js
features: {
  trade: 'プレイヤー同士の交易',
  robber: '盗賊'
}
```

ここに無いキーを `req` / `ban` に書くと、検査で止まる。

#### levels（難易度。★1〜★5 の5つ）

```js
{ lv: 1, name: 'かんたん', desc: '一言で説明できる。' }
```

`name` はガチャのボタン・カード・コピーの文に出る。短く（5文字くらいまで）。

#### cats（ジャンル）

```js
{ key: 'setup', name: '初期配置' }
```

`key` は半角英字。ルールが1件も無いジャンルは画面に出ない。

#### basics（遊び方タブの早見表。2列の表）

```js
{ title: '建設コスト', rows: [ ['街道', '木材1・レンガ1'], ['都市', '小麦2・鉱石3'] ] }
```

#### combos（遊び方タブのおすすめの引き方）

```js
{ name: 'はじめて', pick: '★1〜★2 を2枚', desc: 'いつものゲームに、ちょい足し。' }
```

#### rules（ルール本体）

| 項目 | 要る？ | 説明 |
|---|---|---|
| `id` | 要る | 1 からの通し番号。★の小さい順に並べてから番号を振る（画面では No.001） |
| `lv` | 要る | 難易度 1〜5 |
| `cat` | 要る | `cats` の `key` |
| `title` | 要る | ルールの名前。ほかのルールと同じ名前にしない |
| `text` | 要る | 本文。`\n` で改行 |
| `list` | — | 箇条書き（サイコロの表など）。配列 |
| `note` | — | 補足・ねらい |
| `need` | — | 箱のほかに用意するもの |
| `p` | — | ◯人専用。`meta.players.choices` のどれか。本文にも「◯人専用」と書く |
| `x` | — | 同じ値を1つでも持つルール同士は同時に引かない（同じところを変えるルール）。配列 |
| `req` | — | このルールが前提にする要素（`features` のキー）。配列 |
| `ban` | — | このルールが無くす要素（`features` のキー）。相手の `req` に同じ値があれば同時に引かない。配列 |

両立しない、とは「`x` が1つでも重なる」か「一方の `ban` と他方の `req` が重なる」こと。画面（`app/gacha.html` の `clash`）と検査（`tools/lib.mjs` の `conflicts`）は同じ規則で判定する。

書くときの決まり（検査で見る）:
- 文の中に半角の引用符（`"` `'`）を使わない。「」を使う
- 波ダッシュは「〜」にそろえる（「～」は使わない）
- 上の表に無い項目を足さない

### 3. pairs.json を書く（任意）

「同時に出たら困る組」と「同時に使えるはずの組」を、ルールのタイトルで書く。`x` / `req` / `ban` を直したあとに、止め忘れ・止めすぎが無いかを確かめるためのもの。

```json
{
  "note": "メモ（任意）",
  "mustBlock": [["タイトルA", "タイトルB"]],
  "mustAllow": [["タイトルC", "タイトルD"]]
}
```

### 4. 検査する

```sh
node tools/check_rules.mjs games/<id>
node tools/check_pairs.mjs games/<id>
```

- `check_rules` の最後が `問題: なし` なら通った。問題があると一覧が出て、終了コードが 1 になる
- `check_pairs` が `OK（止めるべき◯組・組めるべき◯組）` なら通った。`pairs.json` が無いときは `未実施` と出る
- 引数を付けなければ、`games/` の全部を検査する

### 5. build する

```sh
node tools/build.mjs
```

`games/<id>/index.html`・`index.html`（一覧）・`dist/artifact/<id>.html` ができる。
`meta.id` とフォルダ名が違うと、何も書かずに止まる。
`app/gacha.html` や `rules.js` を直したら、毎回 build し直す（できたファイルは手で直さない）。

### 6. ブラウザで確かめる

```sh
node tools/serve.mjs
```

`http://localhost:8000/` を開く（GitHub Pages と同じ、http で配った状態になる）。確かめること:

1. 一覧に新しいゲームが出て、押すとそのゲームが開く
2. ガチャ・ぜんぶ見る・遊び方の3タブが出る。件数が `check_rules` と同じ
3. 「ガチャを回す」で引ける。人数の行は `meta.players` のとおり（選択肢が無い・1つなら出ない）
4. スマホの幅（390px）で横にはみ出さない。ライトとダークの両方で読める
5. 開発者ツールのコンソールにエラーが出ない

`games/<id>/index.html` をダブルクリックで直接開いても動く。

### 7. 公開する（GitHub Pages）

GitHub Pages は、リポジトリの `main` のルートをそのまま配る。だから:

1. build でできた `index.html` と `games/<id>/index.html` も、`rules.js` といっしょにコミットする（配られるのはこのファイル）
2. ルートの `.nojekyll` は消さない（Jekyll の処理を止めて、ファイルをそのまま配らせる）
3. ページの中のパスは、すべて相対で書く（`/` で始めない）。リポジトリ名の下（`…/<リポジトリ名>/`）で配られても、一覧 → `games/<id>/` と `rules.js` がそのままたどれる

`dist/` は git に入れない（`.gitignore` に入っている）。

## 見た目（テーマ）を変えたいとき

今は全ゲームがカタンの島の色（海の地・5つの資源の色・六角形）。色は `app/gacha.html` の `/* @tokens-start */` から `/* @tokens-end */` までにまとまっている。

ゲームごとに色を変えるときは、`games/<id>/theme.css` を置く。build がそれを本体の `<style>` のすぐ後ろに足すので、同じ名前のトークンを上書きできる。ライトとダークの両方を、本体と同じ3つの書き方で書く:

```css
:root { --sea: #2d5b3a; --sea-deep: #234a2f; }
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { --sea: #0f2116; --sea-deep: #0a1810; } }
:root[data-theme="dark"] { --sea: #0f2116; --sea-deep: #0a1810; }
```

おもなトークン:

| トークン | 使われているところ |
|---|---|
| `--sea` `--sea-deep` `--sea-shallow` `--sea-line` | 地・タブの溝・切りかえの地・地の六角の線 |
| `--on-sea` `--on-sea-dim` `--on-sea-line` | 地の上の文字・線 |
| `--paper` `--paper-2` `--ink` `--ink-dim` `--line` | カードの紙と文字 |
| `--pick` `--on-pick` | 選んでいるタブ・枚数・チップ |
| `--lv1`〜`--lv5`（`--lv5-b`）と `--lv1-on`〜`--lv5-on` | 難易度の色と、その上の文字 |
| `--forest` `--brick` `--pasture` `--wheat` `--ore` `--sand` | ロゴの六角形・`colorWords` の六角形・「ガチャを回す」（`--wheat`） |
| `--back` `--back-line` | カードの裏 |
| `--font-display` `--font-body` | 見出しの書体・本文の書体 |

色を変えたら、文字と地の色の差（コントラスト）が足りているか、ライトとダークの両方で確かめる。
ロゴの形（7枚の六角形）や地の六角の柄を変えるときは `app/gacha.html` を直す。全ゲームに効く。
一覧（`index.html`）は `app/gacha.html` のトークンをそのまま使う（ゲームごとの `theme.css` は効かない）。

## 保存

画面は、設定・いまのルール・履歴・最後に開いたタブを、ブラウザの localStorage に `house-rule-gacha:<id>:v1` という名前で保存する。同じ場所に複数のゲームを置いても混ざらない。保存できない環境でも、保存しないまま普通に動く。

## dist/artifact/<id>.html

doctype・html・head・body を自分で書かない1枚。外側の骨組みを用意してくれる場所に貼るときに使う。`rules.js` は、その1枚と同じ場所に `rules.js` という名前で置く。`<title>` がゲームの名前に差しかわり、埋め込み先のビューア用の設定（左右の余白の取り方を伝える meta）が1行入っている。

## 公開するときに気をつけること

- 外から読むのは Google Fonts だけにする（API キーや外部の API は使わない）
- ファイルの中（コメントもふくむ）に、個人の名前・メールアドレス・自分のパソコンのフォルダの場所を書かない
- ルールの文は、そのゲームの公式の文章を写さず、自分のことばで書く
- ほかの人から rules.js を受け取ったときは、検査や build を走らせる前に中身を読む（tools は rules.js を JavaScript として実行するため）
